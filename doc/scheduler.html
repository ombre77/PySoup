Scheduler

Schedule Python functions through PySoup's server bridge using immediate, delayed, repeating, and asynchronous execution.

Task functions

A function becomes a PySoup scheduled task with @task(). The function must accept exactly one argument: a Task object.

from pysoup import *

@task()
def run_now(task: Task):
    broadcast("This task was scheduled immediately.")

With no timing decorator, @task() schedules the function immediately through the bridge. The task may still be asynchronous when @async_task() is also applied.

Run once after a delay

@run_later(delay_ticks) schedules one execution after the given number of server ticks. Minecraft runs 20 ticks per second under normal conditions, so 20 ticks is approximately one second.

@task()
@run_later(100)
def delayed(task: Task):
    broadcast("About five seconds later.")

Repeat

@repeating(delay_ticks, period_ticks) waits for the initial delay, then runs repeatedly at the specified period.

@task()
@repeating(20, 100)
def periodic(task: Task):
    broadcast("Periodic task")

Asynchronous execution

@async_task() asks the bridge to execute the task asynchronously. This is useful for work that should not block the server's main thread.

@task()
@async_task()
def background(task: Task):
    # Perform work that is safe to run away from the main thread.
    print("Background work")

Combining decorators

Asynchronous execution can be combined with @repeating():

@task()
@async_task()
@repeating(0, 20)
def async_periodic(task: Task):
    print("Runs asynchronously about once per second.")
Delayed async tasks are not supported. The current implementation explicitly rejects @run_later() combined with @async_task(). Use a repeating schedule with an appropriate initial delay if that behavior is required.

Task cancellation

The callback receives a Task instance. Its id is assigned by the server bridge, and cancel() cancels the registered server task.

@task()
@repeating(0, 20)
def countdown(task: Task):
    print(f"Task id: {task.id}")
    task.cancel()

Calling cancel() before the task has been assigned an ID raises RuntimeError. In normal scheduled execution, the ID is assigned before the callback runs.

Threading guidance

Asynchronous tasks run away from the main server thread. Do not assume that arbitrary Bukkit/Paper operations are safe from an asynchronous callback. If an operation must occur on the main thread, structure the script so that the server-thread operation is scheduled appropriately by the available PySoup bridge/API.

Decorator order

Keep the documented form:

@task()
@run_later(20)
def work(task: Task):
    ...

The scheduling markers are read when @task() decorates the function. The same applies to @async_task() and @repeating().
