Reading errors

PySoup errors fall into Python execution errors, Java/Paper bridge errors, and internal engine failures.

Error categories

CategoryMeaning
Python errorYour script raised a Python syntax or runtime exception.
Java error in bridge callA call crossed into Bukkit/Paper and the Java side rejected it or failed.
Internal engine errorA failure occurred in the GraalVM/Polyglot execution layer.

Python errors

[welcome.py] Python error:
Traceback (most recent call last):
  File "welcome.py", line 5, in <module>
    broadcast("Hello"
SyntaxError: unexpected EOF while parsing

Start with the first traceback location that points into your own script. Typical causes include syntax errors, missing imports, wrong attribute names, and invalid values.

Java bridge errors

[script.py] Java error in bridge call:
NullPointerException: ...

These errors mean that Python successfully reached the Java/Bukkit side but an underlying operation failed. Check the method arguments, object lifetime, and whether the relevant server object is still valid.

Invalid entities

EntityInstance stores a UUID rather than a permanent live Java reference. Methods that need the entity resolve it again. If the entity has been removed or is otherwise invalid, PySoup raises ValueError instead of silently operating on a stale object.

if entity.is_valid():
    entity.teleport(Position(0, 80, 0))

Common mistakes

  • Using an unsupported event: only the events listed on the Events page are wrapped by the current library.
  • Calling a nonexistent convenience method: check the current API reference rather than older examples.
  • Using asynchronous code for main-thread-only work: Bukkit/Paper APIs have thread-safety constraints.
  • Assuming every item stacks to 64: use get_max_stack_size().
  • Forgetting to push a modified player inventory: after changing a PlayerInventory wrapper, call player.push_inventory().
  • Using a removed world/entity: WorldInstance._bukkit_world() and entity resolution validate availability.

Debugging checklist

  1. Identify the script name and error category.
  2. Read the Python traceback from the first useful application frame.
  3. Compare the failing call with the API documented in this site.
  4. If the error crosses into Java, verify that the Bukkit/Paper object exists and is valid.
  5. For scheduling issues, simplify the task to a synchronous minimal callback and add timing/asynchronous behavior back one piece at a time.
